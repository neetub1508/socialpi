What v1 is, how it works, and how it gets built

A tenant signs up, connects their social accounts, buys credits, and types what they want in plain English. An agent plans it, generates any media needed, and publishes — now or at a scheduled time.

The critical path is app review, not code

Four platforms means four developer-app registrations, and Meta, Google and TikTok reviews take weeks and can reject you. Nothing in the codebase blocks starting them.

Day one action: register all four in parallel, before writing application code. Build against X first because it unblocks fastest — the other three are the same connector pattern with different adapters.

Credits are held across the async gap

Prepaid credits exist to solve one specific problem: a post containing a link costs $0.20 on X, thirteen times a plain post. Flat subscriptions bleed money on exactly the users who post most.

Model and isolation

Every tenant-scoped table carries tenant_id and is protected by row-level security. RLS is the isolation boundary — not application code.

TableNotes
tenantsIncludes timezone — required for scheduling.
users, membershipsBetter Auth organisations; role per membership.
social_connectionsPer tenant per platform: handle, scopes, access_token_enc, refresh_token_enc, expires_at, status. Decryptable only by connector.
credit_ledgerAppend-only: delta, reason, ref_type, ref_id, balance_after.
credit_reservationsamount, status (held / committed / released), job_id.
conversations, messagesAgent chat history.
postsstatus, body, media_id, scheduled_for, published_at, platform_post_id, error.
media_assetsR2 key, mime, bytes, provenance.
usage_eventsFeeds OpenMeter; one row per metered action.

Store all timestamps in UTC and render in the tenant's timezone. Scheduling bugs are almost always a timezone stored at the wrong layer.

Security posture

No sandbox, because the agent has a fixed toolset and never executes code it writes. The controls that matter instead:

  • connector is the only service holding token decryption keys. This is the boundary an enterprise buyer will ask about.
  • Tokens encrypted at rest, key from environment, rotated on a schedule. Move to a KMS when a customer requires it.
  • browser-worker hardened: non-root, read-only rootfs, dropped capabilities, seccomp profile, and no network route back to Postgres. It handles untrusted data, so treat it as the most likely thing to be compromised.
  • Spend cap checked before the model call, not after.

If you later add code execution, the isolation step is gVisor with the systrap platform — strong isolation with no hardware-virtualisation requirement, so it runs on ordinary hosts. Firecracker or E2B only if you are running genuinely hostile code at volume.

Done

Definition of done for v1

  • A new tenant can sign up, connect all four platforms, buy credits, and publish to each — immediately and on a schedule.
  • A failed publish releases its credit reservation, and the user sees why it failed.
  • Every agent run produces a Langfuse trace and a metered usage event.
  • A tenant cannot read another tenant's rows, verified by test with RLS enabled.
  • The whole stack rebuilds from the compose file and a database restore on a fresh box in under two hours.

That last one is the deployment-first test. If it fails, you do not have a deployment — you have a machine you are afraid of.
